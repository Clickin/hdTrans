# 사전

사전은 UTF-8 TSV 파일을 담은 폴더입니다. 저장소의 `dicts/`가 기본 사전이며 이 폴더 그대로 배포합니다.

## dicts/ 구성

| 파일 | 계층 | 내용 |
|---|---|---|
| `base.tsv` | `base` | 기본 사전: 일반 어휘·어미·조사·조동사, 품사·의미 코드 |
| `words.tsv` | `words` | 어휘 보충: 명사·동사·형용사·부사·복합어 |
| `words-idioms.tsv` | `words` | 관용구·숙어·사자성어 |
| `words-slang.tsv` | `words` | 속어·구어·인터넷 용어 |
| `words-variants.tsv` | `words` | 기존 단어의 다른 표기: 이표기·가나 표기·반복 부호 |
| `names.00.tsv` ~ `names.02.tsv` | `names` | 인명·캐릭터·지명·단체·작품 이름 (키 순으로 세 파일로 나눔) |
| `names-places.tsv` | `names` | 일본 지명: 역·노선·도도부현·시정촌·명소 |
| `kana.tsv` | `kana` | 한자 단어의 히라가나 표기 |

이 밖에 어미(`endings.tsv`), 구(`phrases.tsv`), 문형(`patterns.tsv`), 의미(`senses.tsv`) 표는 엔진에
내장되어 있어 따로 둘 필요가 없습니다.

## 불러오는 순서

- 사전 폴더 목록을 차례로 불러오며, 뒤 폴더가 앞 폴더를 덮어씁니다.
- 각 폴더에서는 최상위의 `*.tsv` 파일만 이름 순서로 읽습니다. 하위 폴더는 읽지 않습니다.
- CLI는 `-dicts DIR,DIR`, C API는 `hdTrans_Initialize`에 폴더 목록을 줍니다. `J2KEngine.dll`은
  DLL 옆의 `dicts\base`, 그리고 있으면 `dicts\user`를 씁니다.

## 파일 머리줄

`dicts/`의 모든 파일은 다음 두 줄로 시작합니다.

```
#! layer=words
# 속어·구어·인터넷 용어 (JMdict, pixiv백과 용어)
```

- 첫 줄 `#! layer=NAME`(바이트 순서 표시 뒤에 와도 됨)이 파일의 계층을 정합니다. 이 줄이 없으면
  `base` 파일이고, 다른 `#!` 첫 줄은 불러오기를 실패시킵니다.
- 둘째 줄은 파일에 무엇이 들었는지 설명하는 `#` 주석입니다.

## 계층

| 계층 | 형식 | 의미 |
|---|---|---|
| `base` | 열 파일 | 기본 사전. 뒤 파일의 의미가 키와 품사 부류가 같은 앞 파일의 의미를 가립니다. 같은 키의 의미는 `prio`가 높은 순, 그다음 파일·줄 순서 |
| `base` | 일반 파일 | 머리줄 없는 파일은 [사용자 사전](#사용자-사전) 형식으로 읽습니다. 컴파일되지 않는 줄이 있으면 불러오기가 실패합니다 |
| `words` | 열 파일 | 어휘 계층. 의미를 앞 파일의 의미에 더합니다. `replace` 플래그가 있는 의미만 같은 키·부류의 앞 의미를 가립니다 |
| `names` | 열 파일 | 이름 계층. 앞 이름 파일은 가리지만 기본 사전의 의미는 가리지 않습니다. `、`나 `。`가 든 키, 활용형 키, 너무 긴 한국어의 의미는 버립니다. `replace`는 키의 표기를 다시 정합니다 |
| `user` | 열 파일 | 열 형식 사용자 사전. 기본 사전보다 먼저 맞춰 보며 기본 사전을 가리지 않습니다 |
| `kana` | 일반 파일 | `가나<TAB>한자 키<TAB>부류` 줄. 기본 사전 단어의 가나 표기 |
| `readings` | 일반 파일 | `일본어<TAB>읽기` 줄. 이름 읽기 표 (가나 또는 한글) |

열 파일인지는 내용으로 정합니다. 빈 줄과 `#` 주석이 아닌 첫 줄이 `key`로 시작하는 머리글이면 열
파일입니다. `kana`와 `readings`는 일반 파일만, `base`가 아닌 나머지는 열 파일만 가능합니다.
정의: `src/core/dict/snapshot.h`.

### 열 파일

탭으로 구분하며 따옴표나 이스케이프는 없습니다. 첫 줄(머리줄·주석 제외)은 열 이름입니다.

```
key	ko	pos	sem	gram	dict	rule	flags	prio	reading	id
```

- 필수 열: `key`(일본어), `ko`(한국어), `pos`(품사 코드, 예: `N110`), `id`
- 선택 열: `sem`(의미 코드), `gram`(문법 코드), `dict`(사전 코드), `rule`, `flags`, `prio`, `reading`.
  그 밖의 열은 무시합니다.
- 행의 필드가 머리글보다 적으면 나머지는 빈 값이고, 많으면 오류입니다. `rule`과 `prio`는 10진수입니다.
- `flags`: 공백으로 구분한 `xxx`, `kana`, `hidden`, `replace`, `llm`(효과 없음)

## 사용자 사전

머리줄 없는 `.tsv` 파일을 사전 폴더에 두면 사용자 사전으로 읽습니다. UTF-8(BOM 허용), 한 줄에 한 항목:

```
일본어 <TAB> 한국어 [<TAB> 품사[:부류] [<TAB> 옵션]]
```

```
// 주석은 //로 시작합니다. 빈 줄은 무시합니다.
魔導具	마도구
蒼月	아오츠키	surname
ユキ	유키	name
走り回る	뛰어다니다	v5
冷たい	차갑다	adj
ふわふわ	폭신폭신/폭신폭신하다	ono
さん	씨	hon
```

`//`로 시작하는 필드부터 줄 끝까지도 주석입니다. `#` 줄은 주석이 아니므로 일반 파일에는 `//`를
씁니다. 필드는 최대 4개입니다.

### 품사

| 품사 | 의미 |
|---|---|
| `n` (기본값) | 명사 |
| `phrase` | 고정 표현 |
| `name`, `surname` | 이름(또는 성명), 성 |
| `intj`, `lead` | 감탄사 |
| `hon` | 경칭 접미사. 한국어를 비워 둘 수 있음 |
| `v`, `v1`, `v5` | 기본형 동사. `v1`은 일단(る) 동사, `v5`는 오단 동사로 고정. 한국어가 `하다`·`되다`로 끝나는 する 동사는 명사도 추가. `ない`로 끝나는 동사는 형용사로 처리 |
| `adj` | 기본형 い형용사 |
| `na` | 형용동사. 한국어를 `형용사/부사`로 주면 `일본어+に`를 부사로 추가 |
| `adv`, `ono` | 부사와 그 する 동사. 한국어는 `부사/동사 기본형` |
| `end`, `pat` | 문장 끝 어미(문장 끝 서술어에만), 문형. `書く/쓰다`, `高い/높다`, `静か/조용하다`, `学生/학생`의 예문으로 적음: `書いたじゃん<TAB>썼잖아<TAB>end` |

`v`, `v1`, `v5`, `adj`, `na`에는 콜론 뒤에 활용 부류를 줄 수 있습니다: `규칙`, `하다`, `되다`, `이다`,
`ㄹ`, `ㅂ`, `ㄷ`, `ㅅ`, `르`, `러`, `ㅎ`, `우`, `으`. 생략하면 철자로 정합니다(듣다 ㄷ, 돕다 ㅂ, 짓다 ㅅ,
푸다 우, 받침 ㄹ, 르·으 어간, 나머지는 규칙).

### 옵션

공백으로 구분한 `키=값` 또는 플래그입니다.

| 옵션 | 의미 |
|---|---|
| `prio=N` | 키 길이가 같은 항목 사이의 순서 (높을수록 먼저) |
| `final=v\|c\|l` | 한국어의 조사 부류: 모음, 자음, ㄹ |
| `attr=CODES` | 품사 기본값 대신 쓸 의미 코드 |
| `gattr=CODES` | 품사 기본값 대신 쓸 문법 코드 |
| `force` | 더 긴 기본 사전 키 안에서도 기본 후보보다 먼저 |
| `hidden` | 읽기만 하고 불러오지 않음 |
| `space`, `attach` | `hon` 줄: 경칭 앞 띄어쓰기 (기본 `attach`) |
| `register=R` | `end` 줄: 해당 말투의 서술어에만 (`plain`, `casual`, `polite`, `formal`, `archaic` 또는 `해라`, `해`, `해요`, `합쇼`, `하오`) |
| `stative` | `end` 줄: 상태 서술어에만. 같은 어미의 일반 줄보다 앞에 둠 |
| `neg=LEMMA` | `v`, `adj` 줄: 이 단어를 부정하는 한국어 동사 |

정의: `src/core/userdict/userdict.h`.

### 사용자 사전 쓰기

- CLI: 기본 사전 뒤에 폴더를 붙입니다. `hdtrans -dicts dicts,user`
- C API: `hdTrans_Initialize("dicts\0user\0")`, 파일을 고친 뒤 `hdTrans_Reload()`
- `J2KEngine.dll`: DLL 옆 `dicts\user\`에 두고, 고친 뒤 호스트의 사용자 사전 다시 읽기(`J2K_ReloadUserDict`)

## 캐시

처음 불러온 사전은 컴파일한 캐시로 저장되어 다음부터 빠르게 열립니다.

- 위치: Windows `%LOCALAPPDATA%\hdtrans\cache`, macOS `~/Library/Caches/hdtrans`, Linux
  `$XDG_CACHE_HOME/hdtrans` 또는 `~/.cache/hdtrans`. `HDTRANS_CACHE_DIR`(절대 경로)로 바꿀 수 있습니다.
- 캐시는 사전 폴더 목록, 데이터 버전, 포인터 크기, 엔진 데이터와 컴파일러 식별값으로 구분됩니다.
  같은 폴더 목록이라도 다른 빌드는 다른 캐시를 씁니다.
- CLI는 캐시를 만들어 저장합니다. C API와 `J2KEngine.dll`은 있는 캐시를 읽기만 하고 새로 저장하지
  않습니다. DLL에서 쓸 캐시는 같은 빌드의 CLI로 같은 폴더 목록을 주어 미리 만듭니다:
  `hdtrans -dicts dicts -compile-dicts` (만든 캐시 경로나 `up to date`를 출력).
- 캐시 검사는 원본 파일의 크기, 시각, 파일 식별값만 봅니다. 이 값이 그대로인 채 내용만 바뀌었다면
  `-verify-dicts` 또는 `HDTRANS_VERIFY_DICTS=1`로 내용까지 확인합니다.
- 캐시 끄기: `-no-cache`, `HDTRANS_SNAPSHOT=off`, 또는 `HDTRANS_CACHE_DIR`를 빈 값·상대 경로·`off`로.
- 저장된 캐시 세대는 그 자리에서 덮어쓰거나 자르면 안 됩니다. 손상이 확인된 세대는 저장하지 않는
  모드에서도 `.bad` 표시를 남기고 이름을 바꿀 수 있습니다.
